A defensive field guide to LLM and agent security — what can go wrong when the "code" is natural language, and how to stop it before it ships.

Traditional software has a hard boundary between code and data. LLM applications don't: natural language is the instruction set, and the model reads user input, retrieved documents, and tool output through the same channel it reads its own instructions. It can't fully distinguish "the command I was given" from "the content I'm processing" — and that ambiguity is the root of nearly every attack class below.

This is a defensive catalog, not an attack manual. Each entry describes a risk at a conceptual level and ships with a concrete mitigation checklist — there are no working exploit payloads or jailbreak scripts here, by design.

Threats below are mapped to the OWASP Top 10 for LLM Applications where applicable, so you can cross-reference against an established, community-maintained standard.
